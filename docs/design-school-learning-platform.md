# 设计文档:机构在线学习平台(airacm 自建替代)

## 问题陈述

机构当前依赖第三方平台 airacm / appbyme(机务在线学习计费 App)上课和收费,受制于人:抽成高、改不动、数据和规则不可控。目标是**自建一套可控的替代系统**,覆盖注册登录、充值学习、课程权益、(二期)考试自测,并能在微信小程序 + 安卓 + iOS 三端触达学员。逆向 airacm 是为了搞清要复刻哪些能力与流程,不是搬运其内容。

## 需求现状(替代对象)

- 现状:机构在用 airacm/appbyme 第三方平台,被抽成、规则不可控。
- 已有资产:
  - 逆向分析文档(API 清单、流程分析、计费逻辑、JS Bridge 风险矩阵)——作为功能/流程参考。
  - 纯前端 mock 原型(`mock_learning_app`,1572 行,localStorage):已复原「首页模块 → 课程详情 → 登录 → 购物车 → 下单 → 模拟支付 → 权益 → 我的学习/进度」闭环。
- 差距:无任何后端;充值是「按课单买」非「钱包余额」;无考试模块;是网页非安装包。

## 目标用户与最小切入

- 用户:机务/航空从业学员,规模千人以上,未来多机构。
- 最小切入(第一版):**单个机构**跑通「注册登录 + 钱包充值 + 课程学习」闭环,拿到真实付费,完成从 airacm 的切换。多租户在架构层预留(`tenant_id`),不一上来做满。

## 约束

- 不抽成是核心诉求 → iOS 不上 App Store(苹果对虚拟内容强制 IAP 抽 30%),靠微信小程序覆盖 iOS 用户。
- 真实在线收款需微信支付/支付宝商户资质(营业执照+对公账户),审批有周期,与代码并行推进。
- 内容(课程视频、题库)若属 airacm/第三方版权资产,迁移前须确认归属——功能可仿,内容不能搬。

## 已确认前提

1. 第一版先单机构跑通,架构预留多租户,不一上来做满。✅
2. iOS 不上架,用「微信小程序 + 安卓 APK + H5/iOS小程序」绕开苹果 30% 抽成与上架审核。✅
3. 第一版范围 = 注册登录 + 钱包充值 + 课程学习闭环;考试放第二期。✅
4. 支付资质并行去办 —— 用户未确认,**第一版在线支付做成开关,先用后台充值/激活码,不卡上线**。⚠️待澄清

## 方案选型

最终选 **方案 B + 小程序补充**:

- 前端 1:**Flutter**(一套 Dart 出安卓 + iOS 原生),状态管理 Riverpod 或 Bloc。
- 前端 2:**uni-app**(Vue 语法)做**微信小程序**(Flutter 无法编译小程序),覆盖不装 App 的用户 + 绕苹果抽成的 iOS 用户。
- 后端:**模块化单体**(域清晰:账号 / 课程 / 订单 / 钱包 / 考试),多租户从设计阶段预留,留微服务切分边界。
- 数据库:PostgreSQL。视频:对象存储(OSS/COS)+ CDN + 防盗链。
- 两套前端共用同一套 REST API。

代价:维护两套前端(Flutter + uni-app),工量最大。换来双端原生体验 + 全触达 + iOS 不抽成。

### 被否方案
- 方案 A(uni-app 一套出三端):工期最短、最推荐,但放弃了原生体验,用户优先体验选了 B。
- 方案 C(Web SPA 套壳):纯 WebView 套壳无法上架微信小程序,被否。

## 工程评审决策(plan-eng-review)

经工程评审,以下决策已锁定:

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 前端架构 | 坚持两套(Flutter 双端 + uni-app 小程序)。已知工程代价,业务逻辑须下沉后端避免双写 |
| D2 | 钱包并发控制 | **原子 UPDATE 扣减**:`UPDATE wallet SET balance=balance-x WHERE id=? AND balance>=x`,影响行数=1 才发权益,全程一个事务 |
| D3 | 后端框架 | **NestJS (TypeScript)**,与 uni-app 同源、类型可共享 |
| D4 | 多租户 | **行级 tenant_id + 全局过滤**:每张业务表加 tenant_id,NestJS 中间件/拦截器统一注入查询条件 |
| D5 | 支付范围 | **第一版即含微信在线支付** + 激活码/后台充值。商户资质成硬依赖 |

### 必做工程约束(无备选,直接执行)

1. **微信支付回调安全**(D5 拉到第一版 P1):
   - 验签:校验微信签名,拒绝伪造通知
   - 幂等:`transaction_id` 唯一约束,重复通知只入账一次(微信会重发)
   - 对账:每笔 `wallet_txn` 可追溯,定时与微信账单核对
2. **后端强制鉴权**:前端访问控制(mock 的 `canOpenLesson`)仅作 UI 提示;后端每个 `GET /lessons/:id`、视频 URL 必须独立校验权益。客户端判断可被绕过(逆向 JS Bridge 风险已证)。
3. **业务逻辑下沉后端**:权益判断、价格计算等放后端 API,Flutter 与 uni-app 不各写一遍(选两套前端后的 DRY 纪律)。
4. **认证**:短信验证码(需服务商,要实名)+ JWT;微信登录走 code 换 openid。

### 测试要求(第一版核心闭环 100% 覆盖)

5 条 CRITICAL 路径必须含并发/安全测试(会直接亏钱或泄露权益):

| 路径 | 测试 |
|------|------|
| 钱包原子扣费 | 并发双花:同用户并发扣,只扣一次、余额不为负 |
| 激活码充值 | 并发/重复使用只生效一次 |
| 微信回调幂等 | 同 transaction_id 重发只入账一次 |
| 微信回调验签 | 伪造签名拒绝 |
| 课时后端鉴权 | 未购/越权访问被拒(不靠前端) |

E2E:充值→购课→学习 完整闭环(小程序 + 安卓各一遍)。其余路径(注册/登录/列表/订单状态机)happy path + 边界(空态/分页/非法状态流转)全覆盖。

### 性能要求

- 课程列表防 N+1:JOIN 或批量预加载章节/课时/权益,不逐个查。
- 视频走 CDN + 签名 URL,**绝不经应用服务器代理视频流**(会打爆带宽)。
- 复合索引 `(tenant_id, user_id)`;订单/流水表分页必加。
- 课时进度高频写第一版直接写,量大再异步批量。

### 失败模式(关键路径)

| 路径 | 生产失败方式 | 测试 | 错误处理 | 用户感知 |
|------|------------|------|---------|---------|
| 钱包扣费 | 并发双花 / 余额扣负 | CRITICAL 并发测试 | 原子 UPDATE 影响行数校验 | 余额不足明确提示 |
| 微信回调 | 重复通知重复入账 / 通知丢失 | 幂等测试 | 幂等键 + 验签 + 重试 | 充值到账延迟可见 |
| 视频访问 | 越权白嫖 / 签名过期 | 鉴权测试 | 后端校验 + 签名 URL | 受限明确提示 |
| 短信验证码 | 服务商超时 / 被刷 | 限流测试 | 重发限流 + 超时降级 | 重发倒计时 |

### NOT in scope(第一版明确不做)

- 考试/题库模块 —— 二期。
- iOS 上 App Store —— 用小程序覆盖 iOS。
- schema/独立库级多租户隔离 —— 行级 tenant_id 足够。
- 多机构管理后台、分级运营 —— 单机构跑通后再做。
- 视频防盗录(DRM)—— 第一版签名 URL 防盗链,DRM 二期评估。

## 推荐技术栈与数据模型(设计层,非代码)

### 核心数据模型(由 mock 提炼 + 扩展)

| 实体 | 关键字段 | 说明 |
|------|---------|------|
| tenant | id, name, status | 机构(多租户根,第一版仅 1 条) |

| course | id, tenant_id, title, price, original_price, chapter_count, lesson_count | 复用 mock |
| chapter | id, course_id, title, order | |
| lesson | id, chapter_id, title, type(视频/图文), access(free/paid/vip/password) | 访问控制规则沿用 mock |
| order | id, user_id, course_id, amount, status(pending/paid/failed/cancelled), pay_channel(wallet/wechat) | 增加 wallet 渠道 |

| progress | id, user_id, lesson_id, status, position | 课时进度 |
| **二期** question / paper / exam_record / wrong_question | 题库、组卷、成绩、错题本 | 练习自测 |

### 核心闭环
注册登录 → 钱包充值(激活码 / 后台 / 在线支付开关)→ 浏览课程 → 钱包扣费购课、发权益 → 按 access 规则学习课时 → 记录进度。
二期:进入题库 → 随机组卷 → 答题自动判分 → 错题归集。

### 关键 API(设计层)
- 账号:`POST /auth/register`、`POST /auth/login`、`POST /auth/wechat`
- 钱包:`GET /wallet`、`POST /wallet/recharge`(code/在线)、`GET /wallet/txns`
- 课程:`GET /courses`、`GET /courses/:id`、`GET /lessons/:id`(带权益校验)
- 订单:`POST /orders`(钱包扣费)、`GET /orders`
- 进度:`POST /progress`、`GET /progress`

## The Assignment(下一步该做的现实动作)

不是「去写代码」。这个项目能不能成,卡在三件**非代码**的事上,现在就去办:

1. **找机构确认支付资质**:微信支付商户号能不能办、要多久(营业执照+对公账户)。没有它就只能激活码充值。
2. **确认内容版权与可导出性**:airacm 上的课程视频、题库,版权是不是机构的、能不能导出迁移。这决定第一版有没有内容可上。
3. **注册并认证微信小程序账号**:主体认证要时间,越早越好,否则小程序端没法发布。
