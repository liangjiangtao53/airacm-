## 出题规则

### 顺序学习

- 每批固定 20 题。
- 用户下次进入同一科目时，从上次学习进度的下一题继续。
- 按科目筛选时，只从该科目题库出题。
- 到达科目末尾后按题库顺序回到开头，保证能持续学习完整题库。

### 模拟考试

- 按后台配置的科目题量组卷。
- 题目来源为题库随机题 + 当前用户模拟考试错题。
- 有错题时，优先混入一部分未掌握错题；没有错题时，全部从当前科目题库随机抽取。
- 题库不足时返回实际可组卷数量，不重复塞同一题。

默认科目题量：

| 科目 | 题量 |
|---|---:|
| M1 航空概论 | 32 |
| M2 航空器维修 | 50 |
| M3 飞机结构和系统 | 182 |
| M5 航空涡轮发动机 | 70 |
| M9 航空英语 | 60 |
| M9 new | 60 |

后台入口：

- 管理后台 -> 运营配置 -> 模拟考试组卷规则

## 后端实现要点

- 启动时加载题库缓存，避免每次开始考试都扫描数据库题库。
- 只有导入题库、删除题库等题库变更操作会刷新缓存。
- 模拟考试从缓存池内按科目过滤，再按“错题 + 随机题”策略组卷。
- 顺序学习通过 `study_question_progress` 记录每个用户、每个科目的学习游标。
- `exam_paper_rule.categoryCounts` 保存后台配置的科目题量。

## 生产性能测试

测试场景：

- 生产后端容器内直连 API。
- M3 模拟考试。
- 每次组卷 182 题。
- 200 个用户并发开始考试。
- 每个并发请求使用不同 `X-Forwarded-For`，用于模拟真实 200 用户，避免被单 IP 限流误判。

结果：

| 指标 | 结果 |
|---|---:|
| 请求数 | 200 |
| 成功 | 200 |
| 失败 | 0 |
| 整批耗时 | 1449ms |
| 吞吐 | 138.03 req/s |
| p50 | 1134ms |
| p95 | 1383ms |
| p99 | 1391ms |
| max | 1393ms |

结论：

- 新出题规则满足 5 秒内开始考试的要求。
- 当前结果也满足 3 秒内的目标。
- 与上次优化后的性能基本一致，新增“随机题 + 错题 + 科目题量配置”没有造成明显性能回退。

## 限流说明

恢复限流后，单 IP 直接打 200 并发会被后端限流拦截。

实测结果：

- 成功：115
- 失败：85
- 失败原因：`429 Too Many Requests`

这说明限流生效，不代表出题性能不足。真实 200 用户并发应按不同客户端 IP 或合理压测方式评估。
